随着人们生活水平的日益提高，人们对于生活的追求已由温饱转向与健康。同时，因为许多不良商家的恶意生产，导致市面上出现了许多“垃圾食品”，人们的健康因此受到了极大的威胁。通过在医院的长期观察，项目组发现人们的各种疾病都需要多种药品多次服用，并且 特定药品还存在空腹、饭前等日常习惯要求，同时这些疾病往往还伴随着忌口、运动量等要求。这些种种限制叠加在一起，不仅让病人因为时刻需要注意限制而精神劳累，而且往往会因为限制太多病人无法全部顾及进而导致治疗无效功亏一篑。 机会 基于以上背景以及项目 组最新 的调研结果，项目组发现在这一方向仍然存在着许许多多未能解决的痛点，根据调研结果，可以发现的痛点包括： 手动记录麻烦 、 长期 用药易 产生懈怠 等等。 正因如此，项目组力争打造一款能够便利病人用药、辅助病人治疗、帮助医生 一起致力实现理想治疗效果的日常用药软件，并取名为“药知道”。 产品目标 本产品在现有基础上，预期保证病人用户用药约束实际实现情况达到理想情况的 80% 。 产品范围 产品应做内容 （ 1 ）用户用药约束表 通过用户 提供的诊断结果以及医生或者药房的用药嘱咐，产品将这些约束自动按每天的时间顺序整理，并通过闹钟、短信等多种提醒方式辅助用户规范、科学用药，同时为用户减轻负担，使用户不必为此劳神。 （ 2 ）就近就诊导航 本产品将添加定位功能，加入智能算法综合医院强项、实时交通情况、距离等多种因素，实时为用户提供突发状况的最佳紧急就诊方案， 为用户的生命保驾护航。 （ 3 ）药品搜索引擎 用户在使用家用医药箱的长期存放的药物时，难免会出现时间过长说明书丢失等导致无法判断药品功效的问题。同时，在突发状况下，及时科学的利用身边现有的药品，往往可能成为拯救用户性命的关键之举。因此，本产品将提供药品搜索功能。根据药品的名称，智能搜索该药品的具体功效、副作用、饭前饭后、忌口忌食等诸多注意事项。 （ 4 ） 科普文章智能推送 本产品含有科普文章分享平台并附加大数据推送功能，可根据用户的年龄、职位、性别等相关信息推送符合用户个人特征的科普文章供用户学习，从而帮助用户养成科学、健康的生活习惯。 （ 5 ）个人信息墙 产品提供个人登录功能 并且 包含 头像、主题等个性化定制功能。同时，产品 也可根据用户提供的信息为用户提供更符合个人特征的个性化推送。 （ 6 ）药后状况记录表 本产品将给用户提供药后状况记录功能。该功能主要用于用户在用药后及时记录身体的变化，例如：症状是否缓解、是否出现不适等等。从而在用户复诊时能够提供给医生最为详细的病情变化情况。 产品范围之外（未来参考） （ 1 ） AI 聊天 在目前阶段，本产品并未将 AI 聊天功能划入实现阶段。该功能 主要用于为部分不擅长自我搜集信息的用户提供指导，同时将采用更为温和的语气安抚用户的情绪，让用户能够积极应对疾病与治疗。 （ 2 ）多模式选择 在调研结果中，本产品用户并不局限于病人，诊所医生或学者也能成为本产品的用户。因此，项目组将计划在未来推出多模式选择，同时满足对学术性要求性较低的普通用户和对学术性要求较高的学者或医生。 （ 3 ）社交平台（含在职医生认证） 调研结果显示，多数病人都曾有旁人无法感同身受、无人能懂自身情况的“精神孤岛”情况。为此，产品计划为 用户 建立专属的社交平台，旨在 让用户能够跨越距离跨越时间互相激励。同时，该平台还附有在职医生认证，目的是让用户能够辨别部分结论性言论的科学性与权威性。 项目 约束 时间限制 本项目自该文档完成之日，即二零二六年七月十三日起，至同年同月三十一日止，同历时十九天。 人力限制 项目组共 5 SEQ 图 \* ARABIC \s 1 8 用户账户状态转换图 关键业务规则 本节定义 “ 药知道 ” 核心业务运行中的校验、计算、权限及异常处理规则，确保系统在各功能模块中行为一致、数据准确、用户体验可控。 输入与数据校验规则 所有涉及用户输入、外部数据接入及系统内部数据流转的环节，必须执行前置校验，防止 脏数据 进入系统或误导用户决策。 （ 1 ）药品名称输入校验：长度限制 2~50 个字符；仅允许中文、英文、数字 及常用符号（·、 - 、 () ）；禁止输入 SQL 关键字及 HTML 标签。 （ 2 ）用药剂量校验：必须为大于 0 的数字，单位限定为 mg 、 g 、 ml 、片、粒、支；单次剂量上限不超过说明书标注的最大单次剂量。 （ 3 ）手机号校验：必须为 11 位中国大陆手机号格式；验证码为 6 位纯数字，有效期 5 分钟，每个手机号每 60 秒仅能发送一次。 （ 4 ）日期与时间校验：用药计划开始日期不得早于当前日期；结束日期必须晚于开始日期；提醒时间需落在 06:00~23:00 之间。 （ 5 ）定位权限校验：调用 GPS 前必须检查定位权限是否开启；若未开启，提示用户前往系统设置开启，禁止静默调用。 核心指标计算规则 系统涉及多项业务指标的计算，必须保证公式统一、精度一致、结果可复现。 （ 1 ）用药依从率计算：依从率 = 实际打卡次数 / 计划服药总次数 × 100% 。统计周期以自然周为单位，每周一 00:00 重置当周计数。 （ 2 ）就诊推荐得分计算：综合得分 = 距离评分× 0.40 + 科室匹配度× 0.35 + 实时交通系数× 0.15 + 用户口碑评分× 0.10 。其中距离评分按最近医院为 100 分、每增加 1 公里扣 5 分，最低 0 分；交通系数根据实时路况 API 返回的拥堵指数映射为 0~1 之间。 （ 3 ）文章推送匹配度计算：匹配度 = Σ（标签权重 _ i × 用户兴趣度 _ i ）。标签包括年龄区间、性别、职业类型、用药类别、健康关注点；兴趣度由用户历史点击、收藏、分享行为加权计算，最近一次行为权重最高。 （ 4 ）提醒补发判定：用户忽略首次提醒后，系统等待 15 分钟；若仍未处理，补发一次提醒；补发后 30 分钟内仍未响应，标记为漏服并计入依从率分母。 功能权限控制规则 根据用户账户状态（见 4.2.3 状态机），系统对功能访问实行分级控制，确保未授权用户无法访问敏感功能或产生误导性数据。 （ 1 ）未注册用户：可浏览科普文章列表及详情；可使用药品搜索引擎（仅限本地数据库查询）；不可创建用药计划、不可接收个性化推送、不可使用紧急就诊导航。 （ 2 ）待完善用户：可创建用药计划并接收提醒；可使用全部搜索功能；个性化推送使用默认标签（年龄、性别），精度较低；可使用紧急就诊导航但无法保存历史记录。 （ 3 ）正常使用用户：全功能开放；用药依从性分析、历史记录导出、个性化推送精准匹配、就诊导航收藏与历史回顾均可用。 （ 4 ）受限使用用户：核心功能（用药计划、提醒、搜索、导航）不受影响；被关闭的功能（如推送）在设置中显示为灰色 不 可操作状态；用户可随时恢复。 （ 5 ）数据隔离规则：用户 A 的数据（用药记录、搜索历史、收藏文章）在任何情况下均不可被用户 B 访问；后台管理员查询需经过审计日志记录。 异常与降级处理规则 系统在运行过程中可能遭遇网络中断、第三 方服务 故障、硬件权限异常等情况，必须定义明确的降级策略，保证核心功能可用、用户知情权得到保障。 （ 1 ）网络异常：药品搜索时 若网络 断开，优先展示本地缓存结果；若本地无缓存，提示“当前无网络，已为您展示历史常用药品”；用药提醒为本地闹钟触发，不依赖网络。 （ 2 ）定位失败：首次定位失败后，提示用户手动选择所在区域（省 / 市 / 区）； 系统使用缓存的附近医院列表作为降级数据；连续 3 次定位失败后，建议用户检查 GPS 权限。 （ 3 ）数据库查询超时：药品数据库查询超过 3 秒未返回，前端展示加载动画并在 5 根据用户画像标签（年龄区间、性别、职业、用药类别、健康关注点）从文章库中匹配候选文章。 3. 按匹配度公式计算得分（见 4.3.2 推送匹配度计算规则），取 Top 3 篇文章。 4. 通过推送通道发送通知，通知标题为文章标题，摘要为前 30 字。 5. 同时更新 App 首页 " 推荐阅读 " 栏位的文章列表。 6. " 正常使用 " 用户享受精准匹配； " 待完善 " 用户使用默认标签匹配（年龄、性别）。 （ 5 ）异常流程： 1. 推送权限未开启：文章仅更新至首页推荐栏位，不发送推送通知。 2. 文章库无匹配内容：推送通用健康科普文章，标记为 " 默认推荐 " 。 3. 推送通道故障：按 4.3.4 规则降级，文章 列表仍 正常更新至首页。 4. 用户连续忽略 5 篇同类文章：降低该类标签权重 50% ，减少推送频率。 （ 6 ）数据埋点： push_send （推送发送， 含文章 ID 列表）、 push_receive （推送到达）、 push_open （点击推送打开文章）、 push_ignore （忽略推送）、 push_dismiss （清除通知）。 （ 7 ）关联需求： FR-013 （文章浏览）、 FR-002 （用户画像数据来源）、 4.3.2 匹配度计算规则。 FR-013 文章浏览与互动 （ 1 ）功能描述：用户阅读科普文章，可收藏、分享、点赞，系统记录行为数据用于优化推荐算法。 （ 2 ）前置条件：用户已点击推送通知或从首页进入文章列表。未注册用户可浏览但不支持互动。 （ 3 ）后置条件：浏览行为记录入库；用户兴趣标签更新；推荐算法反馈闭环。 （ 4 ）正常流程： 1. 用户点击文章卡片进入文章详情页。 2. 页面展示：标题、作者 / 来源、发布时间、正文内容、配图。 3. 系统开始记录浏览时长（页面可见时计时，切后台或关闭时停止）。 4. 页面底部提供操作栏：收藏、分享、点赞。 5. 用户收藏文章后可在 " 我的 - 收藏 " 中查看。 6. 分享支持微信、 QQ 、复制链接三种方式。 7. 用户退出页面时，浏览行为数据（文章 ID 、浏览时长、是否收藏 / 分享 / 点赞）上报服务端。 8. 服务 端根据 行为数据更新用户兴趣度权重（点击 +1 ，收藏 +3 ，分享 +5 ，浏览 &gt;30 秒 +2 ）。 （ 5 ）异常流程： 1. 文章内容加载失败：提示 " 加载失败，点击重试 " ，展示已缓存的摘要。 2. 未注册用户点击收藏 / 分享 / 点赞：弹出登录引导 " 登录后即可收藏文章 " 。 3. 分享失败（第三方 App 未安装）：降级为复制链接，提示 " 链接已复制到剪贴板 " 。 4. 浏览时长上报失败：本地缓存行为数据，下次启动 App 时补传。 （ 6 ）数据埋点： article_view （文章曝光， 含文章 ID 、来源：推送 / 首页 / 收藏）、 article_read_duration （浏览时长，秒）、 article_like （点赞）、 article_collect （收藏）、 article_share （分享， 含目标 平台）。 （ 7 ）关联需求： FR-012 （文章推荐）、 FR-001 （注册登录控制互动权限）。 非功能性需求 性能要求 页面加载时间、接口响应时间、并发数（ QPS ） 等 安全性需求 数据传输加密、权限控制、敏感信息脱敏、 防刷 机制 可用性 / 易用性 符合可访问性标准、多语言、多时区、常见分辨率 适配 兼容性 浏览器、操作系统、移动设备型号与 版本 可维护性 / 扩展性 日志记录、配置化程度、后续扩展接口 预留 数据合 规 GDPR 、个人信息保护法等要求，数据存储和删除 策略 数据与埋点需求 数据字典 涉及的新增 / 修改字段、枚举值、类型、长度、默认值、是否 必填 埋点方案 事件表（事件名、触发时机、属性、上报方式），与数据分析平台 对齐 统计报表需求 后台要看的指标、看板设计（可附原型 ） 视觉与交互设计需求 设计稿及标注 该产品分为主页、科普、日程表、就诊导航、个人中心五大板块。以下逐一介绍各大 版块 ： （ 1 ）主页：用户登录成功后，首先进入该页面，该页面主要包含日期、当日宜忌、临近日程表事项提醒等基本信息。在页面的最上方，产品设有药品搜索入口，用户可通过该入口查找想要了解的药品的详细信息，包括组成成分、忌口忌食、药物主治等相关信息。 （ 2 ）科普：该产品设有“科普文章”栏目，用户可通过该页面查看符合个人兴趣的科普文章 。在所有提供的文章中，产品还会根据文章内容再划分为中药、西药、养生等主题，以供用户按需选择。 （ 3 ）日程表：该功能为产品核心功能，其下分为三种日程表，分别为服药日程表、病情记录表、药物储量表。服药日程表主要根据用户提供的信息，帮助用户准时服药、科学服药，让用户能够彻底摆脱少服漏服的情况；病情记录表主要为用户提供开始使用药物后每日的身体状况记录，让用户在日后复诊时能够提供准确且详细的身体信息；药物储量表 主要为需要长期治疗的用户服务，该功能依旧用户提供的储药信息，自动为用户计算当前药物储量预计支持的天数，在药物即将服用完时，及时提醒用户购入药物以保证持续服用。 （ 4 ）就诊导航：该产品在该功能中增加了导航和定位功能，但该导航更侧重于医院、诊所等医疗机构的导航。该功能主要为用户提供更为专业的就诊导航，让用户能够根据自身紧急情况，选择合理的就诊方案。 （ 5 ）个人中心：该页面是用户正常使用本产品的前提。用户只有在注册（无 账号）或登录（已在本产品注册）成功后， 才可拥有“个人中心”页面。该功能提供许多个性化设置，例如头像、个性签名等。同时，该页面还有许多辅助性功能 ，“帮助”可以在用户存在疑问时帮助解答，“设置”可以让用户能够将本产品改造地更符合个人使用习惯。 需要注意的是： 以下页面仅做展示，具体尺寸 以及内容请以实际成果为标准 。 主页 1. 登陆成功页 图 STYLEREF 1 \s 8 .
